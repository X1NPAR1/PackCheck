## PackCheck 3.3.1

### Version downgrade
- The version wizard (**Change version** on the server page) can now go to an **older** Minecraft version as well as a newer one.
- PackCheck checks every plugin and mod against the older version, looks for matching builds on Modrinth, and takes a pinned full backup first. It then installs the old server jar and the Java version it needs (for example Java 8 up to 1.16) and test-starts the server. If the test fails, **Roll back** restores everything.
- **Worlds:** an older version cannot open worlds that a newer version has saved, so you choose what happens to them:
  - **Restore the worlds from a backup made on that version.** PackCheck finds the newest full or worlds backup taken on the target version and offers this option by default when one exists.
  - **Start with new worlds.** The current worlds are moved to `old-worlds/<version>-<time>/`; nothing is deleted.
  - **Keep the current worlds.** This is not recommended: the old version usually refuses them or loses chunks.

### Fixes
- World folders are recognised even before Minecraft has saved them for the first time (a `session.lock`, `region` or `dimensions` folder counts, not only `level.dat`). Backups and version changes no longer miss such worlds.
- Long confirmation texts wrap instead of running off the dialog.

### For testing
- The `PACKCHECK_DATA` environment variable points PackCheck at a different data folder (server list, settings, runtimes). This is useful for test runs that must not touch your real servers, and for portable use.
